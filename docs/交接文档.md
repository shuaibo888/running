# 燃赛路跑微信小程序交接文档

## 1. 项目定位

燃赛路跑是面向公司赛事私域用户的微信小程序。产品以“持续记录运动、统一衡量消耗、激励长期参与”为核心，不只服务跑步用户，也覆盖其他运动方式。

首期目标是完成可真实使用的运动记录与激励闭环：用户登录 → 开始运动 → 查看实时数据 → 结束并保存记录 → 查看累计成果、里程碑和排行榜。

## 2. 核心指标

- **统一核心指标：消耗卡路里（kcal）**。不同运动最终都换算为卡路里，用于个人累计、里程碑和排行榜。
- 跑步专项指标：实时配速、运动距离、运动时长和运动轨迹。
- 累计指标：累计消耗卡路里、累计运动次数、累计运动时长、累计运动距离，以及运动覆盖城市数。
- 卡路里属于估算值，应保存计算方式和数据来源，并在产品中明确提示，不作为医疗数据。

## 3. 首期功能范围

### 3.1 用户与微信登录

- 微信小程序授权登录并建立平台用户档案。
- 维护昵称、头像，以及计算卡路里所需的必要身体信息；敏感信息遵循最小采集原则。
- 记录用户所属城市/省份，供地区排行榜使用。

### 3.2 运动记录

- 跑步：开始、暂停、继续、结束运动。
- 运动过程中展示实时配速、距离、时长、轨迹和预估消耗卡路里。
- 结束后保存运动摘要与轨迹，并支持查看历史记录和单次详情。
- 其他运动：选择运动类型，记录时长及必要参数，统一计算或录入预估卡路里。
- 服务端校验异常数据，避免仅依赖客户端上报而产生明显作弊记录。

### 3.3 个人数据与成就

- 展示个人累计卡路里、运动次数、时长、距离和覆盖城市。
- 提供里程碑成就，例如累计卡路里、累计运动次数、累计距离、连续运动天数和覆盖城市数达到指定档位。
- 成就达成后保留解锁时间，避免重复发放。

### 3.4 排行榜

- 首期支持城市榜、省级榜，并预留全国榜。
- 以累计卡路里为主要排行指标，可按日、周、月和累计周期扩展。
- 排行榜必须明确地区归属、统计周期、更新时间、并列规则和异常数据处理规则。
- 运动发生城市与用户排行榜归属地是两个概念，不能直接混用。

## 4. 关键业务对象

- 用户及用户身体信息
- 运动记录
- 运动轨迹点
- 运动类型与卡路里计算规则
- 用户累计统计
- 城市运动足迹
- 成就定义与用户成就
- 排行榜周期快照

## 5. 技术与产品边界

- 后端确定采用单体应用，不拆分微服务；业务代码按用户、运动、轨迹、统计、成就、排行榜和微信接入等领域模块组织，最终由一个主应用统一部署。
- 后端基础框架采用 RuoYi-Vue-Plus 5.6.2（官方 `5.X` 分支，基于 Spring Boot 3.5.15），统一使用 JDK 17、Maven、MySQL 8、Redis、MyBatis-Plus 和 Sa-Token；开发、构建与服务器运行环境均以 JDK 17 为准。
- 微信能力后续通过 WxJava 的小程序模块接入；地图服务商和卡路里算法仍需单独确认。
- 微信小程序端负责定位采集、轨迹绘制和实时展示；服务端负责持久化、统计、校验、成就判定和排行榜计算。
- 轨迹点不能按每个定位点同步写入数据库，应在客户端分段缓存、批量上传并做抽稀或压缩。
- 运动中断、弱网、退出小程序、定位拒绝和定位漂移都必须有明确的恢复或失败处理。
- 持续定位能力、后台运行时长及审核要求受微信小程序平台限制，开发前必须用真机验证，不能把完整 App 的后台运动体验直接视为小程序必然可实现。
- 城市足迹应由有效运动轨迹判定；地区排行榜归属应采用稳定、可审计的用户地区规则。
- 卡路里算法首期采用可解释的估算方案，后续可接入穿戴设备或更精细的运动模型。

## 6. 首期暂不包含

- 赛事报名、计时芯片、赛事成绩同步和证书体系。
- 运动社交动态、群聊、私信和内容社区。
- 商城、积分兑换、广告和复杂会员付费体系。
- 智能手表、手环及第三方健康平台的深度接入。
- 专业训练计划、教练课程和医疗健康建议。

## 7. 开发前待确认事项

- 首期具体支持哪些非跑步运动，以及每种运动需要用户提供哪些参数。
- 卡路里计算是否采集体重、年龄、性别等信息，以及隐私授权文案。
- 排行榜按用户常住地、报名地还是其他规则确定城市和省份归属。
- 日榜、周榜、月榜和总榜中，首期实际上线哪些周期。
- 是否需要轨迹分享、运动海报、好友邀请和企业私域运营入口。
- 小程序持续定位及后台运动能力的真机验证结论。

## 8. 当前项目状态

- 已创建 uni-app 微信小程序前端基础工程。
- 已在 `back/` 引入 RuoYi-Vue-Plus 5.6.2 单体后端基础工程，Maven 编译版本保持为 JDK 17，以匹配服务器环境。
- 燃赛路跑业务模块尚未开发，数据库模型、接口协议、微信接入、地图服务和卡路里算法仍待设计。
- 本文档是当前需求基线；新增功能需先确认是否进入首期范围，再开始实现。
